> **状态**：实现基线（ADR-V2-001..004 已实现；ADR-V2-005 为过程决策）；需求 §19.15/§19.16 的待确认项仍待用户确认

> **变更摘要**：记录 v2（室内农场）四项架构决策与一项过程性决策（构建沙箱）；实现状态与实机证据见 `docs/VERIFICATION.md` §26。

## ADR-V2-001 — 室内槽位农场（D 方案）替代外部农田

**背景**：v1 依赖世界格扫描 + 托管格注册 + 原版作物实体；用户 2026-10-25 决定采用 D 方案：
作物与农田在建筑内部，四档容量 60/150/300/600 改为**抽象槽位**。

**决策**：v2 的所有作物状态只存在于 `IndoorFarmRecord.Slots[]`（纯数据，无坐标）。
生长/收获由模组在建筑内部模拟；原版作物 spec 只作为**数据来源**（生长天数、产物、产量）。

**理由**：避免大范围世界格、可达性、地块冲突与作物实体；性能 O(Capacity)；
四档容量与劳动力解耦（`P_eff = min(Capacity, 工人×38)`）。

**代价与防线**：产物是“模拟收获”，必须保留四道门禁（工人/水/维护/动力），
产物只能来自成熟槽位；面板显示积压与惩罚；文档记录偏离（本节）。

**约束**：`HDBF.Core` 不引用 Unity/游戏（REQ-V2-CORE-04）；禁止任何世界田块 API（REQ-V2-CORE-03）。

## ADR-V2-002 — 3×3×1 平屋顶 + 屋顶叠放

**背景**：v2 四档统一 3×3×1；屋顶必须平、可通行、可作为上方建筑支撑面。

**决策**：模型外包络严格 3×3×1（含装饰）；屋顶顶面为最高点（y≈1.00），顶面 30cm 内无几何；
蓝图顶层块声明 `Stackable: BlockObject`，提供 `Top`/`Floor` 占位与 `GenerateFloorsOnStackable`；
屋顶边缘收边 ≤0.04 且不得阻断上方放置。

**验证**：REQ-V2-BLD-04 要求实机用一座原版小建筑完成叠放 A/B（TC-V2-02）。
若实机证明 1 格高工作建筑不可叠放，**必须报告用户**，再决定加薄平台（2 高）或降低要求，
不得静默放弃（REQ-V2-BLD-07）。

**代价**：3×3×1 的“室内高密度”表达空间有限；用开窗/货架剪影/材质分层补偿（50% 镜头可辨）。

## ADR-V2-003 — 存档 schema v2（槽位数组 + 迁移链）

**背景**：v1 存档记录是地块 ID/作物/疲劳数组；v2 需要 60–600 槽位状态。

**决策**：每个建筑实体仍通过**原生实体持久化**保存（沿用 ADR-001 的决策，不新增全局 `HDBF` 节点），
但记录 schema 升为 v2：`slots` 数组长度 = 档位容量，作物 ID 内联，3 个数值 + 标志；
空槽 crop 为空串、growth=0、fatigue 保留。写前执行 §19.18.3-A2 全量校验（长度/枚举/有限浮点/
范围 clamp/作物白名单/字符串长度）；校验失败不写、保留上一份良好快照、下次保存重试。
v1→v2 尽力迁移：v1 地块数组按序映射槽位，`tank`/维护/模式/端口/适配器保留；失败 → 安全默认
（空槽 + 满水罐 + 默认维护），不删除玩家原版地块/作物。

**理由**：单实体读写天然随实体删除、无孤儿记录；版本化 + 迁移链可追加；预算 100 栋 ≤1.5 MB。

**代价**：跨建筑全局校验仍依赖游戏自身存档完整性（与 v1 相同风险，已记录）。

## ADR-V2-004 — 水模型：内部水罐 + 管道/人工补水

**背景**：v2 没有外部土壤水分；水完全由内部水罐提供。

**决策**：`tank` 由 `WaterMath` 每日结算一次：`demandDay = 活跃槽位 × 每槽日耗 × 模式系数`；
`C = clamp(tank/demandDay, 0, 1)`；`G_irr = clamp((C − 0.25·C_min)/(0.75·C_min), 0, 1)`；
`C < 0.25·C_min` → `G_irr = 0`。补水只有两条**有源**路径：
管道适配器（`IWaterSource`，按当日需求自动补，不囤积超容量）与人工补水
（每趟 1/3 罐、耗 2 个农事动作 + 真实往返，12 格内水源；不可达/污染则失败并提示）。
**禁止逐帧扣水**（REQ-V2-WATER-02）与**无源补水**。

**理由**：水罐是干旱缓冲（3–4 天），管道=自动化、人工=有成本，保持水利玩法重量。

**代价**：新增 `IWaterSource` 接口；管道模组缺失时降级为人工补水（不阻断建筑运行）。

## ADR-V2-005 — 构建沙箱：TEMP 工作根（过程决策，非产品行为）

**背景**：本机 DSH 沙箱为 `workspace-write`；`build.ps1` 默认工作根 `%USERPROFILE%\.hdbf\work`
与部署目录 `Documents\Timberborn\Mods\HDBF` 在当前会话**不可写**；工作区内又不允许出现 DLL
（`build.ps1` 安全门禁）。

**决策**：源码/数据/文档之外的一切构建产物写入 `%TEMP%\hdbf-<tag>`（可写、可删、不进入工作区），
通过 `build.ps1 -WorkRoot "$env:TEMP\hdbf-<tag>"` 或 `-p:HdbfWorkRoot=...` 传入；每个并行任务用独立
`<tag>` 避免 MSBuild 冲突。部署与实机验证需要外层权限时，由 Lead 以一次性提权执行，
并在 `VERIFICATION.md` 记录当天证据。**源码仓库不是 mod 目录**这一不变式不变（无 manifest.json）。

**影响**：README §3 的命令补充该写法；本决策不影响产品行为或发布包结构。
