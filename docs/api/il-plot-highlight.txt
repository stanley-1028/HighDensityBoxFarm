Generated 2026-10-25 from the installed Timberborn 1.1.2.8 managed assemblies with
`tools/ApiIndex` (Mono.Cecil, offline). This file keeps the excerpts that justify the rendering and
input decisions of `docs/workstreams/build-02-plot-highlight.md`; the full dumps were produced in

## 3. Vanilla asset paths and how they are loaded

`Timberborn.Rendering.MarkerDrawerFactory` is public (`game-type-index.txt:22330`) and exposes
`CreateTileDrawer(Color)` / `CreateTileDrawer()`; its backing spec is internal
(`game-type-index.txt:22331` — `BeforeFieldInit` without `Public`), and the mesh/material live in
private `MeshDrawer` fields. The shipped vanilla blueprint names the same two assets:

`%USERPROFILE%\.hdbf\ref\Blueprints\Configurations\MarkerDrawerFactory.blueprint.json`:

```json
{
  "MarkerDrawerFactorySpec": {
    "TileMesh": "Markers/TileMarker",
    "TileMaterial": "Markers/TileMarkerSmall",
    ...
  }
}
```

`AssetRef` loading passes that path string to the public asset loader:

```text
=== Timberborn.BlueprintSystem.AssetRefDeserializer+GenericDeserializer`1<T>::LoadAsset   [Timberborn.BlueprintSystem]
  IL_0009: ldfld Timberborn.AssetSystem.IAssetLoader Timberborn.BlueprintSystem.AssetRefDeserializer/GenericDeserializer`1<T>::_assetLoader
  IL_000f: callvirt !!0 Timberborn.AssetSystem.IAssetLoader::Load<T>(System.String)
  IL_0016: ldfld Timberborn.AssetSystem.IAssetLoader ...::_assetLoader
  IL_001c: callvirt !!0 Timberborn.AssetSystem.IAssetLoader::LoadSafe<T>(System.String)
```

`IAssetLoader` is public (`game-type-index.txt:17784`), so the renderer can load the same two
vanilla assets without reflection or internal types.

## 7. Singleton auto-discovery (why binding the overlay singleton is enough)

```text
=== Timberborn.InputSystem.InputSystemConfigurator::Configure   [Timberborn.InputSystem]
  IL_0002: Bind<Timberborn.InputSystem.CursorService>()
  IL_0006: AsSingleton()
  IL_000c: Bind<Timberborn.InputSystem.InputService>()
  IL_0012: AsSingleton()
```

`InputService` implements `IUpdatableSingleton`, and the game constructs/updates it without any
explicit `MultiBind`; the game-context `HDBF.Gameplay` bindings of
`HdbfPlotHighlightSession`/`HdbfPlotHighlightService` as singletons follow the same convention
(verified in-game for `ILoadableSingleton` by earlier rounds' `HDBF` startup log line).
