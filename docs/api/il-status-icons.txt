Generated 2026-10-25 from the installed Timberborn **1.1.2.8** managed assemblies with
`tools/ApiIndex` (Mono.Cecil, offline). It keeps the excerpts that justify
`docs/workstreams/build-04-warning-icons.md`. Full dumps were produced in the session temp

## 1. Every vanilla building already owns the floating-status pipeline

`Timberborn.BuildingStatuses.BuildingStatusesConfigurator::ProvideTemplateModule` (public type,
`[Context]`-installed by the game) decorates every `BuildingSpec` entity:

```text
  IL_0006: callvirt ... TemplateModule/Builder::AddDecorator<Timberborn.Buildings.BuildingSpec,Timberborn.BuildingStatuses.BuildingStatusIconOffsetter>()
  IL_000c: callvirt ... Builder::AddDecorator<Timberborn.Buildings.BuildingSpec,Timberborn.StatusSystem.StatusSubject>()
  IL_0012: callvirt ... Builder::AddDecorator<Timberborn.Buildings.BuildingSpec,Timberborn.StatusSystem.StatusIconCycler>()
  IL_0017: callvirt Timberborn.TemplateInstantiation.TemplateModule TemplateModule/Builder::Build()
```

`Timberborn.StatusSystem.StatusSystemConfigurator::ProvideTemplateModule` adds the camera and slot
components that make the icon render correctly without any mod-side work:

```text
  IL_0006: callvirt ... Builder::AddDecorator<Timberborn.StatusSystem.StatusIconCycler,Timberborn.CameraSystem.FacingCamera>()
  IL_000c: callvirt ... Builder::AddDecorator<Timberborn.BlockSystem.BlockObject,Timberborn.StatusSystem.StatusSlotOccupier>()
```

The HDBF blueprints ship `BuildingSpec`, so every box farm automatically gets `StatusSubject`,
`StatusIconCycler`, `FacingCamera`, `StatusSlotOccupier` and `BuildingStatusIconOffsetter`. The mod
never instantiates a sprite/prefab/renderer of its own.

The cycler is driven by a singleton updater; its interval is 1.25 s and the per-frame part only
hides a status whose `IsVisible()` became false:

```text
=== StatusIconCyclerUpdater::UpdateSingleton   (excerpt)
  IL_001c: callvirt System.Void StatusIconCycler::UpdateStatusVisibility()   // every frame
  IL_002f: callfloat System.Single UnityEngine.Time::get_unscaledTime()
  IL_0054: callvirt System.Void StatusIconCycler::IntervalUpdate()           // every UpdateInterval

=== StatusIconCyclerUpdater::.cctor
  IL_0000: ldc.r4 1.25
  IL_0005: stsfld System.Single StatusIconCyclerUpdater::UpdateInterval
```

Consequence for BUILD-04: the mod's own 0.5 s pass decides *which* P0/P1 status is active; the
vanilla cycler renders it and updates visibility/scale itself. The mod does not render or animate
sprites, and it avoids the vanilla rotation by keeping at most one relevant toggle active (all
other HDBF toggles are deactivated), so the icon does not flicker between two mod statuses.

## 4. Camera and selection APIs used by the coordinator

`CameraService` is a public singleton; `Transform` is the camera transform and `Target` the camera
focus (used as the "distance in cells" origin):

```text
=== Timberborn.CameraSystem.CameraService::get_Transform
  IL_0001: ldfld UnityEngine.Camera CameraService::_camera
  IL_0006: callvirt UnityEngine.Transform UnityEngine.Component::get_transform()

=== Timberborn.CameraSystem.CameraService::get_Target
  IL_0001: ldfld UnityEngine.Vector3 CameraService::<Target>k__BackingField
  IL_0006: ret

=== Timberborn.CameraSystem.CameraService::Load   (excerpt)
  IL_001d: callvirt UnityEngine.Camera CameraFactory::Create(System.String)
  IL_0022: stfld UnityEngine.Camera CameraService::_camera
```

The camera GameObject is resolved once (`Transform.GetComponent<Camera>()`) and cached in the
coordinator; the per-frame path then only calls `WorldToViewportPoint`. The distance is measured to
`CameraService.Target`, not to the camera, because the camera's own distance is a zoom function
(`CameraServiceSpec.BaseDistance = 32`, blueprint `Configurations/CameraService.blueprint.json`), so
a 40-cell camera-distance budget would hide every icon when zoomed out.

Locating a farm from the aggregation row uses the vanilla selection service:

```text
=== Timberborn.SelectionSystem.EntitySelectionService (public API)
  method public System.Void Select(Timberborn.BaseComponentSystem.BaseComponent target)
  method public System.Void SelectAndFocusOn(Timberborn.BaseComponentSystem.BaseComponent target)
  prop Timberborn.SelectionSystem.SelectableObject SelectedObject {get/set}

=== EntitySelectionService::SelectAndFocusOn
  IL_0001: call System.Boolean EntitySelectionService::IsSelectable(BaseComponent)
  IL_000f: callvirt SelectableObject SelectableObjectRetriever::GetSelectableObject(BaseComponent)
  IL_0017: call System.Void EntitySelectionService::UpdateVisibleLayer(SelectableObject)
  IL_001e: call System.Void EntitySelectionService::SelectSelectable(SelectableObject)
  IL_0025: call System.Void EntitySelectionService::FocusOnSelectable(SelectableObject)

=== EntitySelectionService::IsSelectable   (excerpt)
  IL_0009: callvirt System.Boolean BaseComponent::HasComponent<Timberborn.EntitySystem.EntityComponent>()
  IL_0016: callvirt System.Boolean EntityComponent::get_Deleted()
```

`IsSelectable` only requires a live `EntityComponent`, so passing any component of the farm entity
(the HDBF controller is a `BaseComponent`) is the same path the alert panel uses to jump to a
building. BUILD-04 does not move the camera itself.

## 5. Lifecycle interfaces the new singletons implement

```text
=== Timberborn.SingletonSystem.ILoadableSingleton      method public System.Void Load()
=== Timberborn.SingletonSystem.IUpdatableSingleton     method public System.Void UpdateSingleton()
=== Timberborn.SingletonSystem.IUnloadableSingleton    method public System.Void Unload()
```

`Bindito` configurators bind custom singletons with `Bind<X>().AsSingleton()`, and the game's
`SingletonLifecycleService` drives these methods (same mechanism already used by
`HdbfPlotHighlightService`, which is bound the same way).
